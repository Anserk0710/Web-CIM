# 1. UI Goals

Website harus terasa:

- Professional.
- Credible.
- Modern.
- Medical/healthcare relevant.
- Clean and technical without looking cold.
- Premium without excessive visual decoration.
- Easy to scan on desktop and mobile.
- Fast and predictable for CMS users.

UI harus membantu visitor memahami perusahaan, Product, procurement, activity, career, dan contact tanpa friction.

CMS harus memprioritaskan operational clarity, bukan storytelling motion.

---

# 2. Experience Principles

## 2.1 Clarity Before Decoration

Setiap screen harus menjawab dengan cepat:

- Di halaman apa user berada?
- Apa informasi utama?
- Apa action utama?
- Apa status data saat ini?
- Apa yang terjadi setelah action dilakukan?

## 2.2 Progressive Disclosure

Jangan tampilkan seluruh detail sekaligus bila dapat dikelompokkan.

Gunakan:

- tabs.
- accordions.
- expandable sections.
- settings sidebar.
- dialogs untuk secondary action.

Tetapi jangan sembunyikan informasi kritis seperti error, status publish, permission, atau deadline.

## 2.3 Responsive by Intent

Mobile bukan versi desktop yang diperkecil.

Atur ulang hierarchy, action placement, tables, dan interaction pattern sesuai space.

## 2.4 State Completeness

Setiap data view harus memiliki:

- loading state.
- empty state.
- error state.
- success state jika relevant.
- disabled state.
- permission-denied state bila applicable.

## 2.5 Safe Destructive Actions

Delete/archive/disable harus:

- jelas berbeda dari primary action.
- memiliki confirmation bila impact signifikan.
- menjelaskan target object.
- tidak mengandalkan warna saja.

# 13. Form UX

Every form control must have visible label unless an equally clear accessible labeling pattern is used.

States:

- Default.
- Hover where relevant.
- Focus.
- Filled.
- Error.
- Disabled.
- Loading/submitting.
- Success.

Validation:

- Prefer field-level error near input.
- Add form-level summary for multi-error or server failure when useful.
- Never clear user input unnecessarily after server validation error.
- Required/optional state must be clear.

File upload:

- accepted format.
- max size: CV PDF 5 MiB; image publik 5 MiB/25 MP; brochure PDF 10 MiB.
- Jangan tampilkan CV pada pemilih Media Library publik.
- privacy note for CV.
- progress if upload duration warrants it.
- preview where relevant.
- replace/remove controls.

# 14. Motion System

Motion supports orientation and storytelling; it must not become a dependency for understanding content.

## Scroll Progress

Public pages may show top progress indicator:

```text
2–3px
#0077b6 → #00b4d8
```

## Reveal

Recommended:

- opacity.
- translate Y ~16–24px.
- 400–650ms.

Avoid stagger overload.

## Parallax

Use selectively:

- hero/context visual layer.
- decorative imagery.

Avoid:

- body text parallax.
- strong mobile parallax.
- fast scroll-linked movement.

## Sticky / Pin Scroll

Recommended for service lifecycle on larger screens.

Mobile fallback:

- normal vertical flow.

## Horizontal Product Rail

Support:

- touch.
- trackpad.
- keyboard focus inside cards.
- scroll snapping where helpful.
- visible context hint that content continues horizontally.

---

# 15. Reduced Motion

Respect:

```css
@media (prefers-reduced-motion: reduce)
```

Then:

- disable parallax.
- minimize reveal.
- remove nonessential animated transitions.
- maintain all content visibility.
- avoid motion-dependent navigation cues.

# 16. CMS UX Principles

- Speed.

- Discoverability.
- Safe action.

- decorative parallax.
- storytelling pin sections.

## Activity Editor

- Metadata.

## Career Editor

- Role information.
- Job metadata.
- Responsibilities.
- Requirements.
- SEO.
- Publishing.

Persistent save/publish actions may be used carefully on long editors.

Product/Activity menggunakan aksi terpisah **Simpan Draft**, **Preview**, **Terbitkan**, **Arsipkan** sesuai izin. UI menjelaskan bahwa draft belum mengubah konten live, menandai perubahan belum diterbitkan, dan menampilkan waktu terbit terakhir. Preview memakai login + read permission. Stale lock_version menampilkan konflik dan pilihan memuat data terbaru tanpa membuang input diam-diam.

Career/E-Catalog yang live hanya dapat disimpan oleh update+publish; tampilkan bahwa perubahan langsung memengaruhi publik. Page/Settings live update juga diberi penjelasan. Tidak menampilkan tombol publish seolah semua modul memiliki revision engine yang sama.

# 22. CMS Permission UX

Permission behavior must be explicit.

Examples:

- Hide Create button if user cannot create.
- Hide/disable Publish if user can edit but not publish.
- Direct URL access still returns server-side 403.
- Permission errors should explain lack of access without exposing sensitive system details.

Never rely on client UI alone for authorization.

---

# 23. Loading Patterns

Use:

- skeletons for structured page loading.
- compact spinner for button/action loading.
- progress for file upload when meaningful.

Avoid full-page blocking spinner for minor mutation.

Optimistic UI should be used only when rollback/error behavior is clear.

---

# 24. Empty States

Every empty state should answer:

- What is empty?
- Why might it be empty?
- What can user do next?

Examples:

```text
No products yet.
Create the first Product to make it available for publishing.
[Create Product]
```

CTA must respect permission.

---

# 25. Error States

Error message should be:

- safe.
- actionable.
- contextual.

Use retry where operation is repeatable.

Do not display stack traces, SQL, filesystem paths, secrets, or raw server exception messages to end users.

---

# 26. Toast and Notification Rules

Use toast for transient confirmations such as:

- Saved.
- Published.
- Archived.
- Upload completed.

Do not use toast as the only location for critical validation/error details.

Long-lived status belongs inside the page.

---

# 27. Destructive Actions

Destructive actions include:

- Delete.
- Disable user.
- Remove role permission.
- Remove referenced asset.

Confirmation should name the target when possible.

Example:

```text
Delete Product “ABC Analyzer”?
This action cannot be undone.
```

Prefer archive/soft-delete when business requirements warrant recoverability.

---

# 28. Accessibility

Target WCAG 2.2 AA baseline.

Required:

- Keyboard navigation.
- Visible focus.
- Skip link on public pages.
- Semantic landmarks.
- Correct heading hierarchy.
- Form labels.
- Error association.
- Accessible dialogs/drawers.
- Alt text.
- Status uses text + visual treatment, not color alone.
- Reduced motion.
- Adequate contrast.
- Touch target sizing.

Testing should include keyboard-only navigation for critical flows.

---

# 29. Responsive Reference Widths

Use content-driven breakpoints, but QA must include at least:

```text
320px narrow/reflow
~390px mobile
~430px mobile
~768–820px tablet
1366px desktop
1440px desktop
wide desktop
```

No horizontal page overflow except intentional components such as tables/rails.

---

# 30. Image Guidelines

Priority:

1. Actual Product.
2. Actual company/facility.
3. Actual office.
4. Actual events.
5. Actual training/installations.
6. Contextual stock imagery only when clearly generic.

Never label generic imagery as exact Product or event.

Product image treatment should favor neutral, consistent backgrounds when possible.

---

# 31. SEO-Aware UI

Public UX must not depend on client JavaScript to expose essential content.

Important content should be present in server-rendered HTML.

Avoid UI patterns that hide meaningful crawlable content behind inaccessible client-only rendering.

Breadcrumbs should align with visible hierarchy and structured data.

---

# 32. Performance-Aware UI

Public pages:

- Keep JavaScript minimal.
- Lazy-load noncritical images.
- Reserve image dimensions to reduce layout shift.
- Avoid large animation libraries unless justified.
- Prefer CSS for simple transitions.

CMS:

- Paginate large lists.
- Debounce search appropriately.
- Avoid fetching data unused by current view.
- Use server pagination/filtering for large datasets.

# 35. Mapping konten dan operasional v4

Sumber/field/editor permission/empty behavior setiap section mengikuti dokumen 06 bagian 9. Page form terstruktur cukup; jangan membangun arbitrary page builder. Data dashboard mengikuti read permission sehingga jumlah aplikasi/inquiry tidak terlihat bagi role yang tidak berhak.

CV download dan CSV export adalah aksi terpisah, tampil hanya dengan kombinasi read + izin tindakan. Export menyatakan filter/jumlah baris dan batas 5.000 baris. Retention/anonymized state tidak menawarkan file yang sudah dibersihkan.

Validasi server adalah authoritative. Sukses submission berarti data sudah tersimpan; notification email dapat memiliki status terpisah bagi operator. Duplicate application menampilkan respons jelas tanpa membuat record/file baru atau mengungkap status seleksi.

Sticky header/action bar tidak boleh menutupi keyboard focus; berikan scroll offset yang diuji. Warning unsaved changes membedakan data belum tersimpan dari draft tersimpan namun belum diterbitkan. Focus color memakai token aksesibel Design System, bukan cyan muda sebagai satu-satunya indikator di latar putih.
